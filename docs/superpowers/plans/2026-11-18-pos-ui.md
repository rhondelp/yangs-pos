# POS Ordering UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** The cashier's tablet flow.
- **Floor:** tap an Available or Reserved table to open a tab, or tap an Occupied table to jump to its POS screen.
- **POS screen:** category tabs, search, big product tiles (including unavailable ones, shown disabled), an option picker, and a draft order with steppers, remove and "Send order".
- **Session panel:** previous orders by time, running total, and "Bill" (a read-only bill preview).
- **Layouts:** two panes in landscape; in portrait a bottom bar plus slide-up drawers.
- **Mechanics:** Alpine.js against `/api/v1` over the browser session (Sanctum stateful). Adding items never reloads the page.

**Spec:** owner's Step 10 brief; `design-system/YANGS/MASTER.md`; `docs/superpowers/specs/2026-11-18-open-tab-design.md` (the API being consumed).

## Global Constraints
- Every target is at least 48px (POS actions 56px). Status always has text, never color alone.
- Pages must work with no keyboard: steppers, taps, no text inputs required for ordering. Search is optional.
- Buttons that send requests are disabled while their request runs.
- Session-cookie API calls send the CSRF token from `<meta name="csrf-token">`.
- No cost or margin anywhere on POS screens.

## Rulings
1. **Session-cookie API calls:** enable `statefulApi()` (Sanctum SPA mode).
   - A deactivated user's session must stop working on the API at once: add a check to the `api` group that rejects them with 401. This closes the gap ruled in Step 4.
   - *Cost if wrong:* tablets on a LAN hostname need `SANCTUM_STATEFUL_DOMAINS`, which is documented in the README.
2. **The POS page is server-rendered** with its menu and session passed in as JSON, so the first paint needs no extra request. It includes unavailable products, flagged, so tiles can show an "Unavailable" state. Archived products and categories are excluded. Sending still goes through the API, which re-checks what can be sold.
3. **"Bill" opens a read-only bill preview:** itemized active lines, cancelled lines struck through, and the total. Presenting the bill (Awaiting payment) and taking payment belong to the payments step.
4. **Draft lines live only in the browser** until sent. Tapping the same product and option again raises the quantity. The stepper runs 1–99; the minus button is disabled at 1 and remove is separate.
5. **Out of scope:** item notes (they need a keyboard), and editing or cancelling sent items from the POS. Those have their own permissions and reasons and come with a later step.

## Tasks
1. **Backend (TDD):**
   - `DiningTable::openSession()` HasOne.
   - `statefulApi()` plus a `RejectDeactivatedApiUsers` middleware on the `api` group.
   - `PosController@show` at `GET /pos/sessions/{session}` (`can:pos.create-order`):
     - builds the JSON for the screen: categories, products with an `available` flag and their options, the session, open tabs for the switcher;
     - redirects closed or cancelled tabs to the floor with a message.
   - **Tests:** page renders with the bootstrap; archived items are excluded and unavailable ones flagged; no cost; a closed tab redirects; 403 without permission; a deactivated session gets 401 on the API.
2. **Floor:** Available and Reserved cards open a dialog with "Open tab" (`fetch` POST, then go to the POS page) plus the manual status changes. Occupied and Awaiting payment cards link to their POS page. **Tests:** occupied card links; open button present for users with `pos.open-session`.
3. **POS screen:** `resources/views/pos/show.blade.php` plus `resources/js/pos.js` (`Alpine.data('posScreen')`). Includes the quick table switcher drawer, a toast, and error handling: 422 shows the message, 401 or 419 sends the user to login.
4. **Verify:**
   - Playwright end-to-end at 768×1024 and 1024×768: open a tab, add a plain product, add an option through the modal, step a quantity, remove a line, send, check the session panel total, then open the bill and the switcher.
   - Screenshots: floor, POS, option modal, session panel.
   - Touch audit, the full suite and the build.
