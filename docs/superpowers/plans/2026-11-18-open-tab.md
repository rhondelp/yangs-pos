# Open Tab (Table Sessions and Orders) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Backend and API for the open-tab workflow: open a tab (table → Occupied), add orders (rounds) with price and cost snapshots, update and cancel items under permissions, a running bill, cancel an empty tab. Payment status always stays `unpaid`.

**Architecture:**
- **Services own the rules and transactions:** `TableSessionService` (open, cancel), `OrderService` (addOrder, updateItem, cancelItem) and `RunningBill` (calculate).
- **Order numbers:** `ORD-YYYYMMDD-NNNN`, where the date is the business date (06:00 cutoff) and the number comes from an atomic per-day counter upsert.
- **Stock:** `StockHook` is the empty Phase 3 hook point, called inside the order transactions.

**Tech Stack:** Laravel 13, PHP 8.4, PostgreSQL 18, Sanctum, PHPUnit 12.

**Spec:** `docs/superpowers/specs/2026-11-18-open-tab-design.md` (binding). Also `CLAUDE.md` and `docs/ARCHITECTURE.md`.

## Global Constraints
- **Running commands:**
  - In PowerShell, prefix with `$env:Path = "C:\Program Files\PHP\current;" + $env:Path;` (the shell PATH is stale).
  - Tests: `php artisan test --filter=<Name>`.
  - Tests run on the `yangs_test` PostgreSQL DB with `RefreshDatabase`.
  - Do not run `git commit`.
- **Money:**
  - Columns are `decimal(12,2)` with cast `decimal:2` (strings).
  - All math goes through `App\Support\Money` (bcmath, half-up): `Money::round()`, `sub()`, `percentOf()`, `equals()`, `format()`. Add `add()` and `mul()` there if needed, with unit tests in `tests/Unit/MoneyTest.php`. Never use float.
- **Timezone:** `Asia/Manila`; timestamps are `timestampsTz()` / `timestampTz()`.
- **Models:**
  - Use the `#[Fillable([...])]` attribute (see `app/Models/Product.php`).
  - Eloquent strict mode is on, so eager-load relations used in loops and never assign attributes that aren't fillable.
- **Audit:** every write calls `App\Services\Audit\ActivityLogger::log(string $action, ?Model $subject, array $old = [], array $new = [], ?User $actor = null)` inside the same `DB::transaction`.
- **Errors:** business-rule refusals throw `Illuminate\Validation\ValidationException::withMessages([...])`, so the API returns 422.
- **Permissions:** check with `$user->can('<name>')`.
  - Names: `pos.open-session`, `pos.create-order`, `pos.cancel-session`, `orders.cancel-item`, `orders.discount`, `orders.view-own`, `products.manage`.
  - The Cashier role has `pos.open-session`, `pos.create-order`, `tables.view`, `tables.update-status` and others, but not `orders.cancel-item`, `orders.discount` or `pos.cancel-session`.
- **Existing code to reuse:**
  - `App\Models\DiningTable` (status enum `App\Enums\TableStatus`) and `App\Services\Tables\TableStatusService::change(DiningTable $t, TableStatus $to, bool $system = false, ?string $reason = null)`, which locks and logs.
  - `App\Models\Product` (`sellable()` scope, `price`, `cost`, `variants()`) and `App\Models\ProductVariant` (`price`, `cost`, `product_id`).
  - `App\Services\Catalog\ProductService`, to create test products.
  - `Database\Seeders\RolesAndPermissionsSeeder`.
- **Nothing in this plan writes `payment_status` other than the default `unpaid`.**

## Review Focus
- **Two tablets open a tab on the same table at the same instant:** exactly one succeeds. The other gets 422 "already has an open tab", never 500.
- **Two order numbers created at the same instant on the same business day:** distinct and consecutive. 23:59 and 01:30 share a date; 06:00 starts a new one.
- **Product price changed or product archived after ordering:** existing lines keep their snapshots, and new orders refuse archived or hidden products.
- **Partial cancel of a discounted line:** discounts split so the active and cancelled lines sum to the original; line totals are never negative.
- **Updating or cancelling items on a cancelled tab, or an item from another tab through the API:** 422 or 404, never a silent change.

### Task 3: TableSessionService and StockHook

**Files:**
- Create: `app/Services/Orders/StockHook.php`, `app/Services/Orders/TableSessionService.php`
- Test: `tests/Feature/Orders/TableSessionServiceTest.php`

**Interfaces – Produces:**
- `StockHook::deductForOrder(Order $order): void` and `StockHook::itemCancelled(OrderItem $item, int $quantity): void`. Bodies are empty, each with a comment saying that Phase 3's `StockService` goes here and that it is called inside the caller's transaction.
- `TableSessionService::open(DiningTable $table, User $by, ?string $notes = null): TableSession`:
  1. Lock the table row (`lockForUpdate`).
  2. Refuse if inactive ("not in use"), or if an open/billing session exists ("Table {label} already has an open tab.").
  3. `TableStatusService::change($table, Occupied, system: true)`, which refuses Cleaning and Occupied with its own message.
  4. Create the session (`business_date` = `BusinessDate::for(now())`, `opened_at` = now).
  5. Log `session.opened` with new `['table' => label]`.
  6. Catch `UniqueConstraintViolationException` and rethrow as `ValidationException` (key `table`) with the same message.
- `TableSessionService::cancel(TableSession $session, User $by, string $reason): TableSession`:
  - requires `$by->can('pos.cancel-session')`, otherwise `AuthorizationException`;
  - lock the session;
  - refuse unless the status is open or billing and there are no active items ("Cancel or remove the items first.");
  - set status cancelled, `closed_at`, `closed_by`;
  - table → Available (system);
  - log `session.cancelled` with reason.

- [ ] Tests:
  - Open sets the table to Occupied and logs.
  - A second open on the same table is refused (422 key `table`), and the table stays Occupied with one session.
  - Inactive, Cleaning and already-Occupied tables are refused.
  - A Reserved table can be opened.
  - `business_date` uses the cutoff (`travelTo` 01:30).
  - Cancel works on an empty tab and frees the table.
  - Cancel is refused with active items, refused without permission, and refused on an already-cancelled tab.

### Task 4: OrderService and RunningBill

**Files:**
- Create: `app/Services/Orders/OrderService.php`, `app/Services/Orders/RunningBill.php`
- Test: `tests/Feature/Orders/OrderServiceTest.php`, `tests/Feature/Orders/RunningBillTest.php`

**Interfaces – Consumes:** Task 1 `OrderReferenceGenerator`, `BusinessDate`; Task 2 models; Task 3 `StockHook`.

**Interfaces – Produces:**

**`addOrder(TableSession $session, User $by, array $lines, ?string $notes = null): Order`**
- `$lines`: `list<array{product_id:int, variant_id?:?int, quantity:int, notes?:?string}>`.
- Requires `pos.create-order`; lock the session; refuse unless the session is open or billing ("This tab is closed.").
- For each line:
  - the product must be in `Product::sellable()`, else "{name or #id} is not on the menu right now.";
  - the variant must belong to the product and not be archived;
  - quantity must be 1–99.
- Snapshots: `product_name`, `variant_name`, `unit_price` = variant price ?? product price, `unit_cost` = variant cost ?? product cost (nullable), `discount` 0, `line_total` = `unit_price` × quantity.
- Reference from the generator, using the session's current business date (`BusinessDate::for(now())`).
- Call `StockHook::deductForOrder` and log `order.created` with new `['reference', 'items' => count, 'total']`.

**`updateItem(OrderItem $item, User $by, array $changes): OrderItem`**
- `$changes`: optional `quantity`, `discount`, `notes`.
- Lock the session; refuse if the session isn't open/billing or the item is cancelled.
- Quantity:
  - raising it needs `pos.create-order`;
  - lowering it is refused: "Use cancel to remove items; it needs a reason.";
  - must be ≤ 99.
- Discount needs `orders.discount` (AuthorizationException otherwise) and must be 0 ≤ discount ≤ price × quantity.
- Recompute `line_total` and log `order_item.updated` with old and new of the changed fields only.

**`cancelItem(OrderItem $item, User $by, string $reason, ?int $quantity = null): OrderItem`**
- Requires `orders.cancel-item` (AuthorizationException) and a non-empty reason (max 200).
- Lock the session; refuse if the session is not open/billing or the item is already cancelled.
- No quantity, or a quantity equal to the line's: mark the whole line cancelled.
- Quantity below the line's: split.
  - Reduce the original's quantity.
  - Create a cancelled copy with the same snapshots and the cancelled quantity.
  - Move the discount pro rata: cancelled share = `Money::round(discount × cancelled_qty / qty)`; the original keeps the rest.
  - Recompute both `line_total`s.
- Set `cancelled_by` and `cancelled_at`.
- If no active items remain in the order, `order.status` = cancelled.
- Call `StockHook::itemCancelled(cancelledLine, quantity)` and log `order_item.cancelled` with `['quantity', 'reason', 'line_total']`.
- Return the cancelled line.

**`RunningBill::calculate(TableSession $session): array`**
- `gross` is Σ `unit_price × quantity` over active items, and `discounts` is Σ `discount` over active items.
- `total` is `gross − discounts`, and `item_count` is Σ active quantity.
- `orders` is a list of `{id, reference, created_at, total}`, and `cancelled` is a list of `{id, product_name, quantity, cancel_reason}`.
- Every money value is a 2-decimal string.

- [ ] Tests (each named after the behavior):
  - Multiple orders per session get consecutive references.
  - A price snapshot survives a later price change (`ProductService::update` price 85 → 90; the old line stays 85.00, a new order uses 90.00).
  - Variant price and cost are used; product cost is the fallback; a null cost stays null.
  - Archived, hidden, wrong-variant and quantity 0 or 100 lines are refused, and nothing is created.
  - The running bill is correct over 2 orders with a discount and cancels: exact strings.
  - Cancelled items are excluded from the total and listed separately.
  - A partial cancel splits the line and the discount; the totals sum correctly.
  - A cashier without `orders.cancel-item` is blocked (AuthorizationException) and nothing changes.
  - A discount without `orders.discount` is blocked.
  - Lowering the quantity is refused.
  - Changes on a cancelled tab or item are refused.
  - `StockHook` is called: bind a spy into the container that records calls.
  - After the full flow (open, add, update, cancel, add), every order has `payment_status === unpaid`.
  - Every write left its activity log row.

**Routes** (inside the existing `auth:sanctum` group; every route needs a `can:` middleware because `RouteGuardTest` enforces it):
- `GET sessions` (`can:pos.create-order`): open and billing sessions with table and running total.
- `POST tables/{table}/sessions` (`can:pos.open-session`) → 201.
- `GET sessions/{session}` (`can:pos.create-order`): with orders, items and `bill` (`RunningBill`).
- `POST sessions/{session}/orders` (`can:pos.create-order`) → 201.
- `POST sessions/{session}/cancel` (`can:pos.cancel-session`).
- `PATCH order-items/{item}` (`can:pos.create-order`; the discount permission is checked in the service).
- `POST order-items/{item}/cancel` (`can:orders.cancel-item`).

**Resources:**
- `unit_cost` only when the user `can('products.manage')`.
- Statuses as values, with `payment_status` on orders.
- Money as strings.
- AuthorizationException from services becomes 403 (Laravel default).
