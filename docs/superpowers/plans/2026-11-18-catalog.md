# Categories and Products Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The product module (spec §5): categories, products with price, cost and margin, optional variants, an append-only price history, the owner's management UI with image upload, archive and restore, and `/api/v1` endpoints, including a POS menu endpoint that hides archived and unavailable items.

**Architecture:** Two services hold all the rules. `CategoryService` handles categories. `ProductService` creates and updates products and syncs their variants. Every price or cost change writes a `product_price_histories` row and a `product.price_changed` activity log entry in the same transaction. Money math goes through a new `App\Support\Money` (bcmath, half-up). Products, categories and variants use `HasAuditedSoftDeletes`; price history is append-only (model guard and DB trigger).

**Tech Stack:** Laravel 13, PostgreSQL 18, Blade + `x-ui.*` kit + Alpine (variant rows), Sanctum.

**Spec:** `docs/YANGS_SPEC.md` §5; the owner's Step 7 brief; `CLAUDE.md` (money, audit, no hard deletes); `design-system/YANGS/MASTER.md`.

## Global Constraints

- **Money:** `decimal(12,2)`, cast `decimal:2` (strings), bcmath only. Currency is PHP, shown as `₱1,234.50`.
- **Permissions:** `products.view` reads the catalogue. `products.manage` writes products and categories. The POS menu needs `pos.create-order`. Every route carries `can:`.
- **Seeded categories (production-safe, idempotent):** Beer, Liquor, Cocktails, Wine, Soft Drinks, Water, Food and Snacks, Other Products.
- **Images:** `public` disk under `products/`; jpg, jpeg, png or webp; at most 2 MB; served through the `storage:link`.
- **Archive, never delete.** Price history rows are never updated or deleted.

## Rulings

1. **Price and cost live on the product.** Variants are optional, each with its own price and cost; an order line will reference product plus nullable variant. This follows the brief and replaces ARCHITECTURE.md's "price only on variants, default variant required". The ERD is updated to match. *Cost if wrong:* moving prices to variants later is a migration.
2. **`products.cost` is the cost of one sold unit, at 2 decimals.** Phase 3 adds recipe/WAC cost for products with `track_inventory`; the 6-decimal per-ml question stays with inventory items.
3. **`type` is `drink`, `food` or `other`.** The spec asks for product types without naming them. *Cost if wrong:* a migration that only adds enum values.
4. **Price history records initial values on create** (old value null), so a product's full price story is in one table.
5. **Archiving a category that still has active products is refused** with a clear message. Archiving a product also hides its variants from the menu.
6. **POS list = `GET /api/v1/menu`.** It returns non-archived categories, each with available, non-archived products and variants. The POS screen in later steps uses it.
7. **Margin:** amount = price − cost; percent = amount ÷ price × 100, half-up to 2 decimals. Both are null when cost is unknown; percent is null when price is 0.

## Review Focus

- **Concurrent price edits from two tabs:** the product row is locked in the update, and history records both changes in order.
- **Cost unknown (null):** margin is null, never negative or 100%; the UI shows "—".
- **Decimal strings:** "120", "120.5" and "120.50" compare equal, so no false history rows on save.
- **Upload replaced or removed:** the old file is deleted from disk, and a failed validation leaves the old image.
- **Archived category or product:** not in the menu, not in the default lists, restorable, and visible under the "Archived" filter.

### Task 1: Money support
`app/Support/Money.php`: `equals(?string $a, ?string $b): bool`, `sub`, `percentOf(string $part, string $whole): string` (half-up, 2 dp), `format(?string $amount): string` (`₱1,250.00`, `—` for null). Tests: `tests/Unit/MoneyTest.php`.

### Task 2: Schema, models, seeder
Migrations: `categories` (name unique, sort_order, soft deletes), `products` (category_id, name, description, type, price, cost nullable, image_path, is_available, track_inventory, soft deletes), `product_variants` (product_id, name, price, cost nullable, sort_order, soft deletes), `product_price_histories` (product_id, product_variant_id nullable, field `price|cost`, old_value nullable, new_value nullable, changed_by, created_at; append-only trigger). Models with `HasAuditedSoftDeletes` (price history: guard like ActivityLog). `Product::margin()` returns `['amount' => ?string, 'percent' => ?string]`. `CategorySeeder` added to `DatabaseSeeder`. Tests: `tests/Feature/Catalog/CatalogSchemaTest.php` (seeder idempotent; margin cases; history append-only).

### Task 3: Services
`CategoryService` (`create`, `update`, `archive`, `restore`) and `ProductService` (`create(array): Product`, `update(Product, array): Product`, `setAvailability`, `archive`, `restore`, variant sync). Tests: `tests/Feature/Catalog/ProductServiceTest.php`, covering:
- creation writes initial history and logs;
- a price change writes history and `product.price_changed` with old and new, and leaves earlier history and logs unchanged;
- a non-price edit writes no history;
- variant add, price change and archive;
- category archive refused while it has active products;
- image replace deletes the old file.

### Task 4: Web UI
Routes `products.*`, `categories.*`, `products.availability`, `products.archive`, `products.restore`. Views:
- product list: search, category and status filters, thumbnails, availability toggle;
- product form: Alpine variant rows, image upload or remove, price history panel;
- category list with inline create, plus an edit page.

Nav items. Tests: `tests/Feature/Catalog/ProductWebTest.php`.

### Task 5: API

- cashier: 403 on catalogue writes and reads, 200 on menu;
- guest: 401.

The menu hides archived and unavailable items.
